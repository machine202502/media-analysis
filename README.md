# Video Analysis

Локальный веб-сервис для разбора видео и аудио: расшифровка речи, диаризация, поиск по репликам и агенты, которые отвечают со ссылками на таймкоды.

Всё крутится у вас: Docker Compose + Ollama на хосте. GPU не обязателен (CPU Torch).

## Что умеет

- Загрузка файла или ссылки (YouTube и другие источники через `yt-dlp`)
- Сжатие, распознавание речи (GigaAM), опционально: кто говорит, склейка фраз, правка текста
- Автоимена спикеров по тексту или клички-животные, если имени нет
- Векторный поиск по репликам и по индексу «Ключевые моменты» (карточки тем + агрегаты по ролику)
- Свои индексы по инструкции
- Три агента: **agent-mouse** (быстрый zebra: без сборки индексов, до 4 шагов, без проверки ответа), **agent-bear** (разведка — есть ли в ролике материал; если нет, объясняет почему; если есть, строит индекс под задачу и отвечает по нему) и **agent-zebra** (сам формулирует задачу, ведёт рабочие заметки между шагами, выбирает инструменты, пишет ответ из найденного и проверяет его). Оба отвечают на реплики не про ролик сразу, без анализа. Код: `agent_bear.py`, `agent_zebra.py`, `agent_mouse.py`, общие инструменты — `agent_tools.py`
- Озвучка ответа (Piper, мужской/женский голос)
- Интерфейс на русском

Для ролика короче **1,5 часа** галки диаризации, склейки и правки по умолчанию включены; для более длинного или неизвестной длины — выключены. Их всегда можно переключить перед стартом.

## Состав

| Сервис | Назначение |
|--------|------------|
| `frontend` | React + nginx, порт **8080** |
| `backend` | FastAPI, оркестрация этапов, Ollama, индексы, чат |
| `worker` | Тяжёлая нейросеть: ASR, диаризация, эмбеддинги, скачивание |
| `postgres` | Postgres 16 + pgvector |
| `s3` | SeaweedFS (хранилище медиа) |

Ollama **не** входит в Compose: контейнеры ходят на `http://host.docker.internal:11434`.

## Требования

- [Docker](https://docs.docker.com/get-docker/) и Docker Compose
- [Ollama](https://ollama.com/) на той же машине
- Свободно лучше от **16 GB** RAM; для длинных роликов — больше
- Первый запуск тянет образы, модели Hugging Face и голоса Piper — нужен интернет и место на диске

Проверено на Windows и Linux. На macOS `host.docker.internal` обычно работает из коробки.

## Быстрый старт

### 1. Модели Ollama

```bash
ollama pull qwen3.5:4b
ollama pull qwen2.5-coder:7b
```

Ollama должна слушать `127.0.0.1:11434`.

### 2. Запуск

Из корня репозитория:

```bash
docker compose up -d --build
```

Сайт: [http://localhost:8080](http://localhost:8080)

Проверка API:

```bash
curl -s http://localhost:8080/api/health
```

### 3. Остановка

```bash
docker compose down
```

Данные Postgres, S3, рабочая папка и кэш моделей лежат в Docker volumes (`pg`, `s3data`, `work`, `models`) и после `down` сохраняются. Полный сброс:

```bash
docker compose down -v
```

## Как пользоваться

1. Откройте библиотеку на `http://localhost:8080`.
2. Добавьте файл (**Вручную**) или ссылку (**По ссылке**), при необходимости снимите или поставьте галки этапов.
3. Дождитесь статуса «готово».
4. На странице ролика:
   - **Поиск** — вопрос по репликам и выбранным индексам;
   - **Агент** — сам решает, чем ответить; внизу выбирается agent-bear / agent-mouse / agent-zebra;
   - клик по таймкоду перематывает плеер;
   - при включённой диаризации доступны «Имена спикеров».

В **Настройках** на главной задаются потоки, батчи ASR/диаризации и параллельность этапов (с учётом памяти).

## Переменные окружения

Задаются в `docker-compose.yml` у сервиса `backend` (и при необходимости у `worker`):

| Переменная | По умолчанию | Смысл |
|------------|--------------|--------|
| `OLLAMA_URL` | `http://host.docker.internal:11434` | Адрес Ollama |
| `CHAT_MODEL` | `qwen3.5:4b` | Чат и агенты |
| `MERGE_MODEL` | `qwen3.5:4b` | Склейка, индексы, имена |
| `CORRECT_MODEL` | `qwen2.5-coder:7b` | Правка распознавания |
| `EMBED_MODEL` | `intfloat/multilingual-e5-base` | Эмбеддинги |
| `EMBED_DIM` | `768` | Размерность вектора (должна совпадать с моделью) |

Если Ollama на другой машине, поменяйте `OLLAMA_URL` и убедитесь, что контейнер до неё достучится.

## Разработка

Тесты бэкенда (без Docker-образа тесты в контейнер не копируются):

```bash
cd backend
python -m unittest discover -s tests -v
```

Фронтенд локально:

```bash
cd frontend
npm install
npm run dev
```

Сборка только фронта без пересоздания бэкенда:

```bash
docker compose build frontend
docker compose up -d --no-deps --force-recreate frontend
```

## Замечания

- Первый разбор ролика скачает веса ASR/диаризации/эмбеддера в volume `models` — это может занять время.
- Этапы сохраняют прогресс на диске: перезапуск контейнера не начинает длинный ролик с нуля.
- Это локальный инструмент, не публичный SaaS: в Compose стоят простые пароли Postgres и S3, наружу открыт только порт **8080**.
